# Possible future features

A roadmap of features that could be added to the graphical interface, the
PDF summary or the postprocessing, with notes on how each would be
implemented in the current code base. Written 2026-09-06 against the code as
of commit `a5a287b`. Nothing here is implemented yet.

Conventions used below:

- Paths are relative to the repository root.
- "GUI" means `interface_pyqt/main.py` plus the Qt Designer file
  `interface_pyqt/interface.ui`. `interface.py` is generated by
  `interface_pyqt/convert.sh` and is never edited by hand.
- "Writer" means `src/tranci/write.py`, whose `write_all` assembles
  `spectrum_ci.tex` from one `get_*` function per section.
- `Lowest_States` is the diagonalization result in
  `src/tranci/hamiltonians.py`; `at` is the `Atom` object from
  `src/tranci/atom.py`.
- Effort: **S** (an hour, one or two files), **M** (a day, touches GUI and
  manual), **L** (days, new physics or regeneration of the operator library).

## Checklist for any new GUI parameter

Every widget added to the interface touches several places, so the pure PDF
or postprocessing items below are cheaper than they look relative to GUI ones.

1. Add the widget in `interface.ui` with Qt Designer. Its `objectName` becomes
   a key in `parameters.json`, so choose it once and never rename it. Numeric
   inputs are `QLineEdit` (add the name to the `add_numeric_validators` list
   in `main.py`), integers are `QSpinBox`, flags are `QCheckBox`.
2. Run `interface_pyqt/convert.sh`.
3. If the parameter deserves a formula, add an empty `QLabel` named
   `f_<widget>` next to it in the `.ui` and an entry in `FORMULAS` in
   `interface_pyqt/formulas.py` (mathtext only: no `\text`, no `\mathbf`
   inside `\hat`, no environments).
4. Read it in `read_inputs()` in `main.py` and consume it in
   `hamiltonians.build_hamiltonian` (which reads `p` through the
   `req`/`opt` accessors; use `opt` with a zero default so scripts that build
   a dict without the new key keep working).
5. If it can be swept, add an entry to the `SWEEP` table in `main.py`; if it
   is an operator to plot, add it to `get_operator`. A combobox string with no
   table entry raises `ValueError` at run time.
6. Add it to the parameter table in `hamiltonians.latex_DE` so it shows in
   the PDF, and to the "Parameters" subsection of `doc/tranci_manual.tex`.
7. Loading an old parameter file only warns about unknown keys, so backwards
   compatibility is automatic as long as the new widget has a sensible
   default.

## 1. Library features not reachable from the GUI or the PDF

### 1.1 g-tensor in the PDF and as a sweep (S)

**What.** `gtensor.get_gtensor` and `get_principal_g` are implemented and
documented in the manual but the writer never calls them and no GUI task
plots them.

**PDF.** Add `get_gtensor_section(lowest)` in the writer and call it from
`write_all` after `get_gs_operators`:

```python
def get_gtensor_section(lowest):
  try: gs,axes = lowest.get_principal_g()
  except ValueError: return "" # not a doublet, say nothing
  text = "\\section{$g$-tensor of the ground doublet}\n\n"
  text += "Principal values of $g=\\sqrt{G}$, $G_{ab}=2\\,\\mathrm{Tr}[A_aA_b]$ "
  text += "with $A_a$ the ground-doublet block of $(L+2S)_a$.\n\n"
  rows = [[texnum(g,4),"("+", ".join(texnum(x,3) for x in ax)+")"]
          for (g,ax) in zip(gs,axes)]
  text += longtable("rl",["$g_i$","Magnetic axis"],rows)
  text += matrix2latex(lowest.get_gtensor(),"g")
  return text
```

`get_principal_g` raises for any degeneracy other than two, so the section is
simply omitted otherwise. Consider also mentioning in the text when the
ground state is a non-Kramers doublet (even `ne`), since the pseudo-spin
interpretation is then less standard.

**Sweep.** Add a `plot_gtensor` task next to `plot_degeneracy` in `main.py`:
run `sweep_states()`, call `g.get_principal_g()` on each point inside a
`try`, store `np.nan` triplets when it raises, plot the three principal
values against `xs`, write `GTENSOR.OUT`. Needs a new `QPushButton`
`plot_gtensor` in the Sweep tab of the `.ui` and a `signals["plot_gtensor"]`
entry.

### 1.2 Orbital occupations in the summary and as an operator (S)

**What.** The projectors `at.Operator["dz2"]`, `dxy`, `dxz`, `dyz`,
`dx2y2` (cubic harmonics) and the ten `at.um2 ... at.dp2` (individual
$|m\sigma\rangle$ levels) exist. `templates.write_population` already
writes the ten $m\sigma$ occupations of the lowest states to
`POPULATION.OUT`, but nothing reads it back into the PDF.

**PDF.** Add `get_occupations_table(lowest)` in the writer: one row per
manifold, columns `dz2, dxz, dyz, dxy, dx2y2` and total, values taken from
`hamiltonians.get_representation(lowest.manifolds[i], at.Operator[o])` and
traced (the mean occupation over the manifold, which is basis independent).
Add a second table with the $m\sigma$ occupations of the ground manifold
using `templates.write_population`. Call both from `write_all` after the
eigenstate table. The cubic harmonic projectors of `get_op_dict` carry a
comment "this should be double checked"; a sanity check to ship with the
feature is that for `ne=1`, `O>0` the sum of `dxy+dxz+dyz` occupations of the
ground manifold is 1 (t2g) and `dz2+dx2y2` is 0.

**GUI.** Add the five projector names to `get_operator` in `main.py` and to
the `operator_name` combobox in the `.ui`. `plot_operator` then plots the
projected eigenvalues of the occupation along the sweep with no further
changes.

### 1.3 Correlation entropy per manifold (S)

**What.** `Lowest_States.get_correlation_entropy(wf)` is library-only.

**PDF.** In `get_energies_table` add a column "$S_{corr}$" with
`lowest.get_correlation_entropy(v)` for one representative `v` of each
manifold (`lowest.manifolds[i][0]`). The entropy is a property of the state
not of the manifold, and it can differ within a degenerate manifold when the
basis inside it is arbitrary; document that the disentangled representative
(along `jz`, as the GUI does) is used. Cost: each call lifts 55 one-body
operators to the many-body basis with `one2many`, so cache them once per
`Atom` (store the list of lifted `m0` matrices as `at._entropy_ops`) before
looping over manifolds, otherwise the ne=5 case (252 states, 252 manifolds
at worst) is slow.

### 1.4 Dynamical correlator task (M)

**What.** `get_dynamical_correlator(A, B, es=...)` computes
$\langle A^\dagger \delta(\omega - H + E_0) B\rangle$ averaged over the ground
manifold, see `examples/dynamical_spin_correlator`.

**GUI.** New button `plot_correlator` in the Sweep tab, reusing the
`operator_name` combobox for `A` and two `QLineEdit`s `omega_min`,
`omega_max` (or reuse `initial_value`/`final_value` when the sweep is not
running; better to add dedicated fields to keep `parameters.json` clear).
Compute once at the current parameters (no sweep), plot `ds` versus `es`
and write `CORRELATOR.OUT`. The `dynamicstk` module has an ED path and a KPM
path; the ED path (`dynamical_correlator_ED`) is exact for these small
matrices and should be the default from the GUI.

**PDF.** Optional: a figure of the spin-spin correlator of the ground state
embedded with `\includegraphics` (see 2.4 for the figure mechanism).

### 1.5 Hyperfine coupling toggle (M)

**What.** `hyperfine.add_nucleus(at)` doubles the basis with a spin-1/2
nucleus and adds `at.ix, iy, iz, si`; `build_hamiltonian` already adds
`p.hyper*at.si` and the nuclear Zeeman term when `at.has_nucleus` is set.
The GUI never sets `p.hyper` nor calls `add_nucleus`.

**GUI.** Add a `QCheckBox` `nucleus` and a `QLineEdit` `hyper` (eV) to the
Fields group. In `get_atom()`:

```python
if qtwrap.is_checked("nucleus"):
  from tranci import hyperfine
  at = hyperfine.add_nucleus(at)
```

and set `p.hyper = get("hyper")` in `read_inputs`. Add `"Hyperfine A":
("hyper","eV")` to `SWEEP`.

**Things to check.** `add_nucleus` sets `has_nucleus` in the copy; verify
that `check_all(at)` in `check.py` still passes on the enlarged operators or
skip it when a nucleus is present. `latex_DE` must print the hyperfine term
and the nuclear basis labels `I\uparrow`, `I\downarrow` already exist in the
enlarged basis, so wavefunctions print correctly. The `get_op_dict`
projectors (`dz2` etc.) are not enlarged by `add_nucleus`, so 1.2 must skip
them when `has_nucleus` is true. Only spin 1/2 is implemented; an `I`
spinbox would need `add_nucleus` generalized with spin matrices of dimension
`2I+1`.

### 1.6 Custom crystal field from a file (M)

**What.** `at.one2many(m)` lifts any Hermitian 10x10 matrix in the
$|m\sigma\rangle$ basis (indices 0-4 spin up m=-2..2, 5-9 spin down) into the
many-body space. `wannier.wannier2cf` fits a Wannier crystal field. Both are
script-only (`examples/single_occ_VS_many_occ`, notebook
`custom_crystal_field.ipynb`).

**GUI.** A `QLineEdit` `cf_file` with a "Browse" button
(`QFileDialog.getOpenFileName`) in the Crystal-field group, empty by
default. File format: plain text, 10 rows of 10 complex numbers (numpy
`loadtxt(dtype=complex)` accepts `1+2j`), or two real 10x10 blocks. In
`build_hamiltonian` use `opt("cf_matrix", None)` and add
`atom.one2many(cf_matrix)` when given. Do not use the existing
`atom.cf`/`hopping.op` mechanism, which is a hidden file in `cilib/` read
at `Atom.read` time and adds itself silently.

**PDF.** Print the matrix with `matrix2latex` in the Hamiltonian section
and note that it is in the $|m\sigma\rangle$ basis. Also report its
decomposition into the cartesian operators (`wannier.get_operators`) as a
check for the user.

## 2. Cheap postprocessing of quantities already computed

### 2.1 S², L², J² per eigenstate and term symbols (S)

**What.** `get_table_states` prints only the components `Lx..Sz`, so a
reader cannot assign a term symbol.

**How.** Extend `templates.write_low_energy` with three columns computed with
`hamiltonians.exp_val(wave, at.s2)`, `at.l2`, `at.j2`, and the header of the
table in the writer accordingly. Then for each manifold compute
$S$ from $\langle S^2\rangle = S(S+1)$ (solve `S = (-1+sqrt(1+4x))/2`), the
same for $L$ and $J$, and print a term label
$^{2S+1}L_J$ with $L\in\{S,P,D,F,G,H,I\}$ when the values are within
`numberformat.guess_tol` of a half-integer multiple; otherwise print
"mixed". Put the label in a new column of the manifold table of
`get_energies_table`. This is exact only in the free-atom limit (no crystal
field), which the text of the section should say; with crystal fields `L` is
not conserved and the label is only a hint.

### 2.2 Racah parameters next to the U multiplier (S)

**What.** The Coulomb prefactor is dimensionless. For `u*at.vc` the Racah
parameters are `B = 52.9*u meV`, `C = 210*u meV` (checked against the d²
term spectrum, see the manual and `CLAUDE.md`).

**How.** In `latex_DE` add two rows after the `U` row:
`("Racah $B$ (implied)", "$B$", num(52.9*U), "meV")` and the same for `C`.
Define the two constants once in `hamiltonians.py` (e.g. `racah_B_per_U`,
`racah_C_per_U`) so the manual, the GUI tooltip and the PDF cannot drift.
Also worth showing in the GUI as a read-only label that updates on
`textChanged` of the `U` field.

### 2.3 Transition matrix elements between manifolds (S)

**What.** Electron paramagnetic resonance (EPR) and inelastic tunnelling
intensities are governed by $|\langle e|(L+2S)_a|g\rangle|^2$ and
$|\langle e|S_a|g\rangle|^2$ between the ground manifold and the excited
ones. All ingredients are in `lowest.manifolds`.

**How.** New writer section `get_transitions(lowest, nmax=10)`:

```python
gs = lowest.manifolds[0]
for i in range(1, min(nmax+1, len(lowest.manifolds))):
  ex = lowest.manifolds[i]
  for (op,name) in [(mx,"M_x"),(my,"M_y"),(mz,"M_z")]:
    block = np.array([[algebra.braket_wAw(e,op,g) for g in gs] for e in ex])
    w = np.sum(np.abs(block)**2)/len(gs)   # basis independent inside manifolds
```

with `mx = at.lx+2*at.sx` etc. and `braket_wAw` from
`dynamicstk/algebra.py`. Print one row per excited manifold with $\Delta E$
and the three weights, plus the same for $S_a$. Summing $|.|^2$ over both
manifolds makes the number independent of the arbitrary basis inside each
degenerate manifold. A "forbidden" transition is a zero row, which is the
selection rule.

### 2.4 Level diagram figure in the PDF (S)

**What.** A picture of the manifolds with their degeneracy is easier to read
than the table.

**How.** In the writer, before `build_latex`, draw with matplotlib
(`matplotlib.use("Agg")` is not needed since only `savefig` is called):
horizontal lines at each `ex[i]` (meV), length proportional to or annotated
with the degeneracy, the first `nmanifolds_body` manifolds only, saved as
`levels.pdf` in the working directory. In the LaTeX add
`\usepackage{graphicx}` to `PREAMBLE` and
`\includegraphics[width=0.6\linewidth]{levels.pdf}` in the Spectrum section.
`save_tranci` already copies `*.pdf`, so the figure travels with the summary.
Library callers of `write_all` get the figure file next to the `.tex`.

### 2.5 Thermodynamics versus temperature (S)

**What.** Magnetization $\langle L_a+2S_a\rangle_T$, susceptibility,
specific heat and entropy from Boltzmann weights. `hamiltonians.eigenstates`
diagonalizes the dense matrix, so `lowest.evals`/`evecs` are the complete
spectrum (the `n` argument is ignored) and the partition function is exact
at any temperature.

**How.** New module `src/tranci/thermo.py`:

```python
kB = 8.617333262e-5 # eV/K
def thermal_average(lowest, op, T):
  w = np.exp(-lowest.evals/(kB*T)); w /= w.sum()
  return sum(wi*hamiltonians.exp_val(v,op) for (wi,v) in zip(w,lowest.evecs))
def specific_heat(lowest, T): ...  # (<E^2>-<E>^2)/(kB T^2)
def entropy(lowest, T): ...        # -kB sum w ln w
```

Susceptibility either by finite differences of the magnetization in `b`
(re-diagonalize with `b ± db`, reuse `build_hamiltonian`) or, cheaper, the
Van Vleck formula from the matrix elements of `M_a` between eigenstates,
which needs no re-diagonalization. GUI task: a "Plot versus T" button with
`T_min`, `T_max` fields, writing `THERMO.OUT`. PDF: a small table at a few
temperatures, or the figure of 2.4 extended with the Boltzmann population.

### 2.6 Zero-field splitting parameters of the ground multiplet (S)

**What.** When the ground manifold of the spin-only problem (no SOC) is a
$2S+1$ multiplet that SOC splits, the usual experimental parameters are the
axial and rhombic constants $D$ and $E$ of $H = D S_z^2 + E(S_x^2-S_y^2)$.
The existing effective-Hamiltonian fit (`effectivehamiltonian.py`, jax)
returns a generic expansion.

**How.** Without jax: project $H$ onto the lowest $2S+1$ states, project
$S_x,S_y,S_z$ on the same block, build the matrix representation of
$S_z^2$ and $S_x^2-S_y^2$ in that block and solve the linear least squares
problem for $D$, $E$ and a constant with `numpy.linalg.lstsq`. Report the
residual so that the user knows when the spin Hamiltonian does not describe
the block. Only valid if the projected $S^2$ is close to $S(S+1)$ with
constant $S$, which should be checked and printed.

## 3. GUI and workflow gaps

### 3.1 Save sweep figures and data (S)

**What.** The four sweep tasks call `py.show()` and nothing writes the
figure; `save_tranci` copies only `*.tex, *.pdf, *.OUT, *.json`.

**How.** In `plot_eigenvalues`, `plot_degeneracy`, `plot_operator` call
`fig.savefig(name+".png", dpi=150)` (and `.pdf`) before `py.show()`, with
`name` derived from the task and the swept variable
(`sweep_energies_SOC.png`). Add `"*.png"` to the `patterns` list of
`save_tranci`. Optional: a checkbox "Append sweep to summary" that writes
the figure into a `sweeps.tex` fragment included by the next `write_all`.

### 3.2 Headless command-line mode (M)

**What.** Every run writes `parameters.json`, `build_hamiltonian` accepts a
dict and `write_all` needs no Qt. A CLI would allow batch runs and tests
without a display.

**How.** New script `bin/tranci-cli` (and `.bat`) calling
`src/tranci/cli.py`:

```
tranci-cli run parameters.json [--outdir DIR] [--no-pdf]
tranci-cli sweep parameters.json --variable SOC --from 0 --to 0.1 --steps 20
```

Move the non-Qt logic of `main.py` (`get_b`, `read_inputs` turned into
`params_from_dict`, `SWEEP`, `get_operator`, `run_pdflatex`) into
`src/tranci/gui_core.py` or similar, and have both `main.py` and `cli.py`
import it. The JSON keys are the widget names, so `params_from_dict` maps
`"B"` to `babs`, `"j"` to `jabs` and computes the vectors exactly as
`update_fields` does. This would also give the project its first
automatable smoke test (`tranci-cli run examples/gui/params.json`).

### 3.3 Wavefunctions in the cubic-harmonic basis (M)

**What.** `get_latex_wavefunction` prints Slater determinants of
$|m\sigma\rangle$. For crystal-field dominated states a determinant of
$d_{xy}, d_{xz}, ...$ orbitals is far more readable.

**How.** The rotation to real orbitals is a 10x10 unitary $U$ (block
diagonal in spin; the 5x5 block is the standard $Y_{lm}\to$ real harmonics
matrix, cf. `wannier.ylm2xyz_l2`). Lift it to the many-body basis as the
unitary $\mathcal{U}$ of Slater determinants (product of single-particle
rotations; `edtk/states.py` has the machinery for one-body operators but not
for the exponential map, so the practical route is
`scipy.linalg.expm(at.one2many(logm(U)))` since `one2many` of an
anti-Hermitian generator gives the many-body generator). Apply
$\mathcal{U}^\dagger$ to each eigenvector and print with a basis whose
labels are `dxy` etc. instead of `m`. The existing
`wavefunction_z_axis` rotation (`rotate_wavefunction_axis`) is the template
for this: it already rotates eigenvectors with a many-body unitary before
printing. A combobox `wf_basis` with entries "m, sigma" and "cubic" selects
the basis.

### 3.4 Magnetic field in tesla (S)

**What.** `B` is entered in eV (it is $\mu_B B$). Users think in tesla.

**How.** Either a second read-only label showing the conversion
(`1 T = 5.7883818060e-5 eV`) next to the `B` field, updated on
`textChanged`, or a combobox `B_units` with `eV`/`T` read in `read_inputs`
to scale `p.babs`. The second option changes the meaning of the saved `B`
key, so the unit choice must be saved too (it is, automatically, since the
combobox is a widget). Print both in the PDF parameter table.

### 3.5 Two-parameter sweeps and anisotropy maps (M)

**What.** Only one parameter is swept at a time. Magnetic anisotropy is
naturally a map of the ground energy or the gap versus the field direction
$(\theta,\phi)$.

**How.** Anisotropy map: new task `plot_anisotropy` that loops over a grid
of `theta_b` and `phi_b` (reuse `steps` for both), stores the ground energy
and the first gap, plots with `pcolormesh` and writes `ANISOTROPY.OUT`.
Generic two-parameter sweep: a second `sweep_variable_2` combobox with its
own range; `initialize_sweep` generalizes to `fsweep(x, y)` setting two
attributes. Both cost `steps**2` diagonalizations; for ne=5 (252x252) one
diagonalization is a few ms so a 50x50 grid is seconds.

### 3.6 Run in a background thread (M)

**What.** Long sweeps freeze the window; `busy()` disables it but the event
loop only breathes through `processEvents` inside `run_sweep`.

**How.** Move the sweep into a `QThread` (or `concurrent.futures`) and
report progress with a signal connected to `progress.setValue`. Matplotlib
figures must be created in the main thread, so the worker returns the arrays
and the main thread plots. Adds a "Cancel" button. Only worth it once 3.5
exists.

## 4. Larger items

### 4.1 Stevens operator input (L)

**What.** Crystal fields are entered as cartesian polynomials of $l$. The
literature uses Stevens operators $B_k^q O_k^q$ ($k=2,4$, $|q|\le k$).

**How.** Build the 5x5 single-particle matrices of $O_k^q$ from the
standard tables (`l_z`, `l_\pm` polynomials) in a new
`src/tranci/stevens.py`, lift with `one2many`, and expose a small table of
$B_k^q$ entries in the GUI (a `QTableWidget`, which `qtwrap.get_all_inputs`
does not know about, so the serialization must be extended). Print the
Stevens decomposition of any crystal field in the PDF (project the cartesian
crystal field on the orthogonal set of $O_k^q$) as a bridge between the two
conventions. Fully compatible with the existing fields, which are just linear
combinations of the same operators.

### 4.2 Independent Slater or Racah parameters (L)

**What.** The Coulomb term is a single precomputed tensor with a fixed
$F^2/F^4$ ratio, scaled by `U`. Real ions need `B` and `C` (or $F^2,F^4$)
independent, plus $F^0$ which only shifts all $n$-electron states equally
and is irrelevant here.

**How.** The C++ generator in `src/tranci/cpplib` writes `vc.op` per
electron count. Extend it to write three files `vc_F0.op`, `vc_F2.op`,
`vc_F4.op` (one per Slater integral, unit prefactor) and have `Atom.read`
load them into `at.vc_F2`, `at.vc_F4`, keeping `at.vc` as the current
combination for compatibility. Then the GUI can expose `F2` and `F4` in eV,
or `B` and `C` in meV converted with $B = (9F^2-5F^4)/441$,
$C = 5F^4/63$. Needs the Eigen path in `compile.sh` fixed and a full
regeneration of `cilib/`; validate against the d² term energies
`5B+2C, 15B, 12B+2C, 22B+7C` already used in the manual.

### 4.3 Point-group irrep labels (L)

**What.** Labelling each manifold with the irreducible representation of the
point group of the crystal field (e.g. $T_{2g}$, $E_g$ for $O_h$, or the
double-group labels with SOC).

**How.** Generate the point-group operations as many-body unitaries
(rotations from `expm(-i θ n·L)` lifted with `one2many` for the orbital
part, times the spin rotation), compute the characters
$\chi(R) = \mathrm{Tr}_{\text{manifold}} \mathcal{U}_R$ on each manifold and
match against the character table. Requires character tables for the
handful of groups the cartesian fields can produce ($O_h$, $D_{4h}$,
$D_{3d}$, $D_{2h}$) and their double groups when SOC is on. Detect the group
from which parameters are non-zero rather than asking the user.

### 4.4 Ligand-field or charge-transfer extension (L)

Adding ligand $p$ orbitals (a $dL$ or $d^{n+1}\underline{L}$ model) changes
the basis size and breaks the 10-orbital assumption in `one2many`,
`entropy.py`, `wannier.py` and the basis reader. This is a different code
rather than a feature, and is listed only to record that it was considered.
